    Root Cause in extractAgentPayloadObjectText(flightText) (lines 275–298 of v2.1):

    JavaScript

    ...

    This fails on current Arena Agent Mode pages for three reasons:
        Hardcoded first-key assumption ('{"messages":['): v2.1 only looks for a JSON object whose very first property right after { is "messages":[. As soon as another property precedes "messages" in the serialized Next.js Flight props (e.g., {"session":{...},"messages":[...]} or {"id":"...","messages":[...]} or {"initialMessages":[...]}), "messages":[ is preceded by a comma , instead of {, so flightText.indexOf('{"messages":[') returns -1.
        Unresolved Flight row references ($hex): In Next.js React Flight (self.__next_f.push), messages, individual message objects, or message.parts can be outlined as Flight row references (e.g. "messages":"$1a", "messages":["$1b","$1c"], or "parts":"$1d"). v2.1 only extracted :T<hex>, text records and checked Array.isArray(message?.parts) before resolving Flight references.
        Raw :T<hex>, text segments left in flightText during JSON scanning: v2.1 scanned flightText for JSON braces before stripping out raw :T<hex>, text segments, and used a slow per-character new TextEncoder().encode(char) loop.

    What was missed inside .txt exports (formatEvaluationAsText & formatAgentPartAsText):
