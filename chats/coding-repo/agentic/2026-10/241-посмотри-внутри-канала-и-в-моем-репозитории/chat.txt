## Состав и ожидаемый сценарий работы

1. `Client_Bot.dist/Client_Bot.exe` — интерфейс, проверка обновления, авторизация ключом доступа, приём сигналов, настройки и запуск торгового процесса.
2. При старте создаётся `UpdateWindow`; при отличающейся версии программа может скачать ZIP релиза и заменить локальные файлы.
3. Клиент соединяется по Socket.IO с `http://38.54.13.68:5000`. При вводе ключа отправляет событие `check_key` с полями `key`, `hwid`, `version`.
4. HWID формируется с использованием WMI: `Win32_BaseBoard.SerialNumber` и `Win32_Processor.ProcessorId`.
5. Обработчик авторизации проверяет полученный JWT через `jwt.decode(..., pub_key, algorithms=['RS256'])`. Открытый ключ читается из `public_key.pem`. Этот JWT — не торговый PAT-токен.
6. События `market_signal` записываются в `Signals.json`. Сам обработчик записи не выполняет отдельной криптографической проверки содержимого сигнала.
7. Пользователь сохраняет APP_ID, торговый TOKEN и выбор счёта в `Saves.json`. Кнопка START запускает `build_open/Open.dist/Open.exe` через `subprocess.Popen`, рабочая папка задаётся явно. Повторное нажатие в соответствующей ветке вызывает `terminate()` дочернего процесса.
8. `Open.exe` читает настройки и сигналы, обращается к Deriv, получает торговый WebSocket URL, формирует предложения и покупки контрактов CALL/PUT. Сохраняет баланс, статусы, историю и журнал.

Отдельного установщика в рассматриваемом сценарии не выявлено: структура соответствует запуску приложения из папки. Остановка локального процесса сама по себе не означает отмену уже купленных брокерских контрактов.

## Подтверждённые риски

### 1. Незашифрованное соединение с сервером автора — высокий риск

Адрес зашит как `http://38.54.13.68:5000`, а не HTTPS. По этому соединению отправляются ключ доступа, аппаратный идентификатор и версия; принимаются сигналы.

Следствие: отсутствует транспортная защита TLS на предусмотренном кодом соединении. Сетевой посредник потенциально может читать/менять незашифрованный обмен. Проверка JWT с RS256 в авторизации полезна, но не шифрует соединение и не заменяет проверку подлинности каждого торгового сигнала.

**Отправка торгового PAT-токена на этот IP в просмотренных путях не обнаружена.** Не следует смешивать ключ доступа Alpha и токен Deriv.

### 2. Торговый токен в открытом JSON — высокий риск

`save__token` записывает введённое значение в поле `TOKEN` объекта JSON, далее вызывает `json.dump` для `Saves.json`. Шифрование или использование Windows Credential Manager/DPAPI в этом пути не обнаружено.

Следствие: копия папки программы, резервная копия или процесс с доступом к этому файлу могут получить токен. Не отправляйте `Saves.json` вместе с диагностикой. Фактический ущерб зависит от прав выданного токена.

В торговом модуле токен включается в `Authorization: Bearer …`, APP_ID — в заголовок `Deriv-App-ID`. Базовый адрес: `https://api.derivws.com/trading/v1/options`. Публичный WebSocket по умолчанию: `wss://api.derivws.com/trading/v1/options/ws/public`. В настройках предусмотрено переопределение `MARKET_WS_URL`.

### 3. Автоматическая замена программы без обнаруженной проверки подписи пакета — высокий риск

Обновление проверяется через `https://api.github.com/repos/Pelimescha/Alpha/releases/latest`. Код сравнивает строку версии на неравенство с текущей, а не доказывает, что версия новее. Затем выбирает ZIP-asset и использует `browser_download_url`.

Путь обновления скачивает архив, распаковывает через `ZipFile.extractall`, ищет `build/Client_Bot.dist`, создаёт BAT и запускает его через `cmd.exe /c start`. BAT ждёт завершения Client_Bot, использует `robocopy /MIR`, очищает временную папку и запускает новый EXE. Из зеркалирования исключаются `Saves.json`, `settings.json`, `Signals.json`, `History.json`.

В исследованном пути **не обнаружена проверка подписи обновления или сверка с независимо доверенной контрольной суммой**. HTTPS защищает транспорт к GitHub, но не от компрометации издателя или публикации опасной версии. `public_key.pem` используется в авторизации, а не как доказанная защита обновления.

`robocopy /MIR` также может удалять лишние файлы в целевой папке. Приложение следует держать в отдельном каталоге, не вперемешку с личными файлами.

В PE certificate directory обоих EXE размер равен нулю: встроенная Authenticode-подпись не обнаружена. Это не доказывает вредоносность; каталожная подпись отдельно не проверялась.

### 4. Наращивание ставки по типу догона — высокий финансовый риск

В торговом модуле заданы `AMOUNT = 1`, `SOOTNOSENIA = 2.3`, `MAX_ZDELCA = 7`. В `buy_at_candle_close` увеличивается счётчик и выполняется `AMOUNT = round(AMOUNT * SOOTNOSENIA, 1)` для продолжения серии в пределах лимита. Основной цикл ограничивает серию по этому счётчику и сбрасывает начальную ставку для следующей серии.

При последовательном прохождении семи покупок расчёт ставок даёт:

`1 → 2.3 → 5.3 → 12.2 → 28.1 → 64.6 → 148.6`

Сумма — **262.1** при начальной ставке **1**. В запросе предложения указана валюта USD. Это арифметическая иллюстрация предусмотренной лестницы, а не результат реально выполненных сделок: брокер может отклонить покупку, денег может не хватить, серия может завершиться раньше.

Лимит числа ступеней — не гарантия приемлемой просадки. Такой механизм не доказывает положительного математического ожидания.

### 5. Локальная оценка WIN/LOSS не равна подтверждённому расчёту брокера

В исследованном алгоритме `candle_matches_direction` проверяет направление свечи. В `buy_at_candle_close` совпадение направления при счётчике больше 1 приводит к `WIN`; после покупки предусмотрена ветка записи `LOSS` и увеличения ставки. `calc_series_profit` вычисляет прибыль по сумме ставок и `payout` из записи предложения, исходя из переданного локального итогового статуса.

В просмотренном основном торговом модуле не обнаружен путь запроса окончательного расчёта конкретного контракта через `proposal_open_contract` или иной явно выделенный механизм сверки каждого результата. Баланс при этом запрашивается у Deriv отдельно.

Следствие: локальная история и надписи WIN/LOSS **не являются независимым подтверждением фактического результата контракта**. Нужна динамическая проверка на демо со сверкой ID контрактов, времени покупки/экспирации, реальных выплат и баланса. Само по себе это наблюдение не доказывает намеренную подделку результатов.

## Что не подтверждено

В двух исследованных прикладных модулях не найдены подтверждённые пути:

- чтения браузерных хранилищ паролей/cookies или Telegram `tdata`;
- установки автозапуска через Run-ключи/планировщик;
- отключения антивируса, запуска PowerShell для скрытых действий;
- внедрения в чужие процессы, клавиатурного перехвата или майнинга;
- вывода средств на счёт автора;
- отправки торгового PAT-токена серверу Alpha.

Этот перечень означает **«не обнаружено в исследованном коде»**, а не «исключено во всей сборке». Отсутствие ключевых строк не является полноценным антивирусным тестом. Загрузка новой исполняемой версии через обновление, напротив, подтверждена кодом и описана выше.

При старте проверяется релиз GitHub в `Pelimescha/Alpha`. Обновление скачивается, распаковывается, BAT-файл заменяет содержимое папки и перезапускает EXE.
