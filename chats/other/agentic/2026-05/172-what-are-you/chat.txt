While Arena.ai provides a powerful environment, there are some practical and technical limitations designed to keep the system stable and fair for everyone. Since you aren't paying directly, the platform manages resources using the following constraints:

### 1. Resource & Time Limits
*   **Execution Time:** Individual commands (like a Python script or a search) have a timeout (usually 120 seconds). I can't run long-running background processes or permanent servers.
*   **Compute Power:** The sandbox has limits on CPU and RAM. It’s great for data processing and script execution, but it isn't meant for heavy tasks like training large machine learning models or high-end video rendering.

### 2. Network Isolation
*   **The Sandbox:** My `bash` tool (where I run code) is generally sandboxed. It can't freely browse the open web or connect to your private local network.
*   **External Data:** I must use my specific `web_search` and `fetch_page` tools to get data from the internet. I can't just `curl` any random API from within a script unless the platform specifically allows it.
*   **UI Previews:** If I build a website or a dashboard for you, the "Preview" window in the workspace is restricted for security. It won't load external images or scripts from other websites (CDNs) to prevent tracking and security leaks.

### 3. Context & Persistence
*   **Memory:** While I have a "long" memory within a single conversation, there is an upper limit to how much text (tokens) we can exchange before the oldest parts of the conversation start to fade.
*   **Workspace Persistence:** Files you see in the sidebar (under `/home/user`) persist throughout our session. However, system-level changes—like installing a new Linux package via `apt-get`—usually won't survive if the environment restarts or between different chat sessions.

### 4. Rate Limiting
*   To keep the service free and available, there are limits on how many messages you can send or how many complex "agentic" tasks I can perform in a certain timeframe. If you hit a limit, you might have to wait a bit before continuing.

### 5. Safety & Content Filters
*   I have built-in safety guidelines. I cannot generate malicious code (malware), help with hacking, or create content that violates safety policies.

### How to work within these limits:
*   **Break tasks down:** Instead of "Build a whole startup," ask for "Create a project structure," then "Write the data processing script," then "Design the HTML frontend."
*   **Keep it local:** Use the workspace to store and process data rather than trying to connect to external databases.

**Is there a specific project you're worried might be too big or complex?** I can help you figure out the best way to approach it!
